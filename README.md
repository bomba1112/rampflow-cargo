# RampFlow Cargo (Stage 0)

Внутренний вспомогательный инструмент Ground Supervisor (ASG Business Aviation, Баку, cargo).
Связывает ULD из LIR с тележками, ищет их, фиксирует начало и конец загрузки.
Не заменяет LIR, load control и процедуры. **Только вымышленные данные.**

## Запуск

```bash
npm install
npm test            # 24 теста ядра
npm run build       # dist/ (для хостинга) и dist-single/ (один файл)
npm run check       # тесты + сборка + UI smoke-тест
```

Открыть `dist/index.html` через любой статический сервер (`npx serve dist`).

## Структура

| Папка | Что внутри | Переносится на Flutter |
|---|---|---|
| `src/core` | модель, команды, селекторы, хранилище событий. Без DOM | да, 1:1 в Dart |
| `src/ui` | экраны, тексты (`strings.ru.js`), CSS | нет, заменяется Flutter UI |
| `src/web` | IndexedDB / localStorage | нет, в Flutter будет Drift/Isar |
| `tests/` | `core.test.mjs` (логика), `ui-smoke.mjs` (клики в jsdom) | тесты ядра портируются |

## Главные правила модели

1. Позиция в самолёте (AR, 11P), ULD, рабочая позиция тележки (группа + порядок от тягача), одиночная 20 ft и наблюдение места это **разные вещи**.
2. Источник правды: журнал событий (append-only). Состояние пересобирается. Отмена это событие `ACTION_UNDONE`.
3. Номер группы всегда строка ("007"). Приложение не подсказывает «следующий». Повтор на рейсе только предупреждает.
4. «Передана на high loader» не равно «загружена в самолёт». Статус `LOADED_CONFIRMED` зарезервирован и не используется.
5. Место сцепки неизвестно, пока его не отметили. Водитель приложением не пользуется.
6. 20 ft тележка всегда одна, без суффикса.
